# Assistant Blueprint

## Purpose
Define a future niche AI assistant only after repeated workflow patterns are proven through real client delivery.

## Productization rule
Do not build this assistant until:
- repeated use case appears across multiple clients
- the workflow is stable
- required input fields are known
- outputs are predictable enough for templating
- manual QA effort is low enough to justify productization

## Candidate assistant types
- intake assistant
- proposal drafting assistant
- client brief assistant
- inquiry summarizer
- response drafting assistant

### Productization signals
- repeated request type
- repeated output structure
- low variation in workflow
- low correction rate
- obvious UI or form pattern

## Recommendation template
At the end of a blueprint, include:
- should this become a product now?
- what is still too variable?
- what minimal version is safe to test?
