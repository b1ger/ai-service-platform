# Edge Cases

## Purpose
Track cases that require more caution or adaptation.

## Edge Case 1 — Very vague inbound request
### Example
"I need some work done, can you help?"

### Required handling
- do not classify too aggressively
- request only the minimum necessary missing details
- avoid sending a long questionnaire immediately

---

## Edge Case 2 — Sensitive or regulated communication
### Example
Clinic or medical reminder workflow.

### Required handling
- maintain manual review boundaries
- avoid over-automation in sensitive communications
- keep message templates conservative

---

## Edge Case 3 — Prospect asks for everything at once
### Example
They want inquiry handling, reminders, proposals, CRM, and reporting immediately.

### Required handling
- narrow the scope to one first workflow
- propose phased rollout
- make exclusions explicit

---

## Edge Case 4 — Client has no existing structure at all
### Example
Everything lives in chat and memory.

### Required handling
- start with the simplest visible workflow
- avoid assuming tools or systems exist
- provide very lightweight delivery artifacts

---

## Edge Case 5 — Strong emotional or informal brand voice
### Example
Owner wants messages to sound casual, local, or very direct.

### Required handling
- adapt tone in templates
- keep workflow logic stable
- separate tone customization from process design
